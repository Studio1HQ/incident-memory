# ByteRover + Claude Code Incident Memory Demo

This repository demonstrates how to capture, store, and reuse incident knowledge directly inside a codebase using ByteRover and Claude Code.

The project uses a deliberately flawed payment service to show how a real production bug is analyzed, fixed correctly, and permanently documented so it cannot be reintroduced.

## What This Project Shows

You will see a complete end-to-end workflow:

- An unfamiliar codebase analyzed purely from source
- Automatic documentation generated from code behavior
- A real rollback bug identified and reproduced
- A correct, idempotent fix implemented
- Incident knowledge stored as structured context
- Future bug prevention using `brv query`

This is not a toy README. It is a reference implementation for institutional memory.

## Project Scenario

The service is a FastAPI-based payment demo with an intentional bug.

Bug summary:

- A rollback operation credits user balances
- The operation is not idempotent
- Retries cause duplicate credits
- This simulates a real-world financial incident pattern

## How This Repo Was Built

### 1. Initialize ByteRover

```

brv init

```

This creates ByteRover rules and enables context capture.

Screenshot: ByteRover initialization output

### 2. Curate the Codebase Context

```

brv curate

```

Claude analyzes the entire repository and generates structured documentation based only on code behavior.

Generated artifacts include:

- System overview
- Entry points
- Execution paths
- Shared state
- Bug analysis
- Demo workflow

Screenshot: Curated documents summary

### 3. Sync Context to ByteRover

```

brv push

```

This publishes the generated knowledge so it is queryable by future engineers and agents.

Screenshot: ByteRover dashboard after push

### 4. Design and Implement the Fix

Prompt used:

```

Using the existing ByteRover context and current codebase, design and implement a correct, idempotent fix for the double-credit bug, explain why previous behavior failed, update the code accordingly, and document the approved fix and rollout considerations as markdown.

```

The fix:

- Adds an idempotency guard
- Enforces valid state transitions
- Prevents duplicate balance updates
- Documents rollout and reconciliation steps

Screenshot: Claude fix summary and code edits

### 5. Commit the Fix

The rollback fix is committed to the repository so the code and context evolve together.

Screenshot: Commit confirmation

### 6. Prevent the Bug from Returning

A future engineer can query the system before writing code:

```

brv query "What patterns should I follow when modifying user balances in payment operations?"

```

The response surfaces:

- The original bug
- Why it happened
- The approved idempotency pattern
- Code references
- Rollout constraints

No debugging from zero. No repeated mistakes.

Screenshot: Query response showing prevention guidance

## Why This Matters

Most teams already write postmortems.

The problem is that postmortems are not present when code is written.

This repository demonstrates:

- Context stored next to code
- Knowledge surfaced at coding time
- Bugs prevented, not just fixed
